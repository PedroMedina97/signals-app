Servicios con Estado: BehaviorSubject vs Signals

Servicios Stateful: Los servicios con estado mantienen y gestionan datos compartidos entre componentes. Tradicionalmente se usaban BehaviorSubjects de RxJS, pero signals ofrecen una alternativa más simple y reactiva sin necesidad de suscripciones manuales.

Enfoque Tradicional: BehaviorSubject

// Servicio con BehaviorSubject
private itemsSubject = new BehaviorSubject<Item[]>([]);
items$ = this.itemsSubject.asObservable();

// Componente necesita suscribirse
ngOnInit() {
  this.service.items$.subscribe(items => {
    this.items = items;
  });
}

// Importante: limpiar suscripciones
ngOnDestroy() {
  this.subscriptions.unsubscribe();
}

Enfoque Moderno: Signals

// Servicio con Signals
private itemsSignal = signal<Item[]>([]);
items = this.itemsSignal.asReadonly();

// Computed signals automáticos
total = computed(() => 
  this.items().reduce(...)  
);

// Componente: acceso directo sin suscripciones
// En el template se accede directamente a los signals
// service.items() y service.total()

Comparación Directa

Característica BehaviorSubject Signals
Suscripciones Manuales (subscribe) Automáticas
Lifecycle hooks OnInit, OnDestroy requeridos No necesarios
Memoria Gestión manual (unsubscribe) Gestión automática
Valores derivados Operadores RxJS (map, combineLatest) Computed signals
Complejidad Mayor (pipes, operators) Menor (simple y directo)
Performance Buena Mejor (más eficiente)
Compatibilidad Toda versión de Angular Angular 16+

Recomendación

Para nuevos proyectos con Angular 16+, usa Signals en servicios stateful. Son más simples, más eficientes y reducen el boilerplate. Reserva RxJS para casos complejos de programación reactiva como streams de eventos, debouncing, o múltiples fuentes asíncronas.
