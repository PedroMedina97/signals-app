Signal Inputs

Los Signal Inputs reemplazan a @Input() tradicional. Son señales reactivas que se actualizan automáticamente cuando cambian los valores del padre, eliminando la necesidad de ngOnChanges, ChangeDetectorRef o setters manuales. Se interpolan con paréntesis: {{'{{'}}nombre(){{'}}'}}.

Signal Outputs

Los Signal Outputs son eventos que emiten valores desde el componente hijo hacia el padre. Similar a @Output() pero con mejor integración con signals. El padre escucha el evento y actualiza su estado en consecuencia.

Model Inputs (Two-Way Binding)

Los Model Inputs crean un binding bidireccional automático usando la sintaxis [(propiedad)]. Combinan un input y un output en uno solo, permitiendo que el hijo actualice directamente el signal del padre sin necesidad de eventos manuales.

Uso de viewChild()

viewChild() retorna un signal que contiene una referencia a UN elemento del template. Devuelve Signal<ElementRef | undefined> porque el elemento puede no existir aún. Se resuelve automáticamente cuando el DOM está listo, sin necesidad de ngAfterViewInit.

Input REF con Effect: Este input se enfoca automáticamente mediante un effect.

Uso de viewChild() desde componente padre

viewChild() con componentes: Permite acceder a métodos y propiedades públicas de un componente hijo. El padre puede invocar métodos del hijo directamente usando la referencia obtenida con viewChild().

Uso de viewChildren()

viewChildren() retorna un signal con un array de referencias a MÚLTIPLES elementos que comparten la misma template reference. Devuelve Signal<ElementRef[]> y se actualiza automáticamente cuando se agregan o eliminan elementos.

Timing de Child Queries con Signals

Timing de resolución: Las queries basadas en signals se resuelven automáticamente cuando los elementos están disponibles en el DOM. Los effects detectan estos cambios inmediatamente. Los elementos condicionales (@if) se resuelven dinámicamente al aparecer/desaparecer.

Host Bindings y Host Listeners con Signals

Host Bindings y Listeners: En lugar de usar decoradores @HostBinding y @HostListener, Angular moderno usa la propiedad host en el metadata del componente. Los bindings usan sintaxis de template y se integran perfectamente con signals, permitiendo reactividad automática en propiedades y estilos del elemento host.

Binding Router Data to Component Inputs

Router Input Binding: Con withComponentInputBinding() habilitado, los route params, query params y route data se vinculan automáticamente a los inputs del componente. Elimina la necesidad de inyectar ActivatedRoute y suscribirse manualmente a los observables.

Todos los tipos de datos:

El route data (category, featured) se define en la configuración de rutas y también se vincula automáticamente.

Producto Completo
Cómo funciona:
  1. provideRouter(routes, withComponentInputBinding()) habilita el binding automático
  2. Los route params (/product/:id) se mapean a inputs con el mismo nombre
  3. Los query params (?color=red) se mapean a inputs con el mismo nombre
  4. Los route data (data: {category: 'x'}) se mapean a inputs con el mismo nombre
  5. Todos son signals reactivos que se actualizan automáticamente
